# DEEP CONTRACT, CHARTER OF THE ELDERDARK, LATE FEES and DOWN THERE — working notes for Claude

Four games in one repo, sharing an engine (`src/engine/`, with its own README; `runGame` in `run.ts` is each page's whole entry point, and every engine export needs a doc comment, `tests/engine/docs.test.ts`, for the generated reference at `/engine/`). Vite + TypeScript, no UI framework. DEEP CONTRACT is an intentional homage to the *Alien* films (names stay our own). The root page (`index.html`, `src/picker/`) is a game picker that only links to the games and imports nothing but `src/engine/`. The About page (`about/index.html`, `src/picker/about.ts`) sits with it: who made the games, the source on GitHub, and the Ko-fi tip jar; every game's settings link to it.
- **DEEP CONTRACT** (`/contract/`, `contract/index.html`, `src/main.ts`): retro-futurist idle clicker (Alien-flavoured, original IP) with a slow-burn horror turn.
- **CHARTER OF THE ELDERDARK** (`/forest/`, `src/forest-main.ts`): dark-fantasy company management in a corrupting forest (Symbaroum-flavoured, original IP). Design and status are in `docs/forest/DESIGN.md`. Code lives in `src/forest/` (pure simulation, same rules as missions), `src/forest-data/` and `src/forest-ui/` (ledger UI, `ledger.css`). It has its own save key (`elderdark.save`).
- **LATE FEES** (`/late-fees/`, `src/late-fees-main.ts`): modern-day slasher homages on a video store shelf (VHS look). Venues × killers, the counterpart of scenario × horror: `src/late-fees/` (pure simulation; venues `camp/`, `clinic/`, `insurer/` and `asylum/`, killers `drowned/`, `burned/`, `design/` and `patient/`, the shared film arc in `story.ts`, sequels in `sequels.ts`), `src/late-fees-data/`, `src/late-fees-ui/` (`vhs.css`). Its save key is `latefees.save`. Design and status are in `docs/late-fees/DESIGN.md`.
- **DOWN THERE** (`/down-there/`, `src/fathom-main.ts`; the code keeps its working title FATHOM): the deep-water monster game, from sharks off a resort beach down to kaiju from a breach in the trench. `src/fathom/` holds the pure simulation (zones `shallows`, `shelf`, `open-water`, `trench`, `breach`, with seasons for prestige), plus `src/fathom-data/` and `src/fathom-ui/` (`sonar.css`). Save key `fathom.save`. Design and status: `docs/kaiju/DESIGN.md`. Its play-as-the-horror tier is the Source (`src/fathom/deep.ts`).
- **CLIP WORKS** (`/clips/`, `src/clips-main.ts`): the engine's example game, the classic paperclip loop, built from the engine's docs alone (`src/clips/`, `src/clips-ui/`). It imports only the engine; when it needs something the engine lacks, fix the engine. Its README lists the gaps building it showed.
- **Boundaries** (`tests/architecture.test.ts`): `src/engine/` imports nothing from either game, no game imports another (LATE FEES included), and the picker imports only shared code.
- **One service worker** at the site root serves every page; each page registers it, and each game ships its own manifest from `public/contract/`, `public/forest/`, `public/late-fees/` or `public/down-there/` so it installs as its own app.

Read before changing things:
- `docs/DESIGN.md`: premise, economy, the five acts and their pacing targets, prestige, UI/art direction.
- `docs/BOARDROOM.md`: the second tier (built): WARDEN promoted to headquarters, chartering contracts run by their own WARDENs (`src/core/boardroom.ts`, `src/ui/boardroom.ts`, `src/data/boardroom/`), and the architecture rules it relies on.
- `docs/TERRAFORM.md`: the terraforming scenario and the **scenario × horror** architecture (built).
- `docs/ROADMAP.md`: what's built, deliberate deviations from the original plan, and the backlog.
- `docs/late-fees/DESIGN.md`: the third game, LATE FEES (modern-day slasher homages, VHS look, venues × killers, sequels). All three tapes, the six crossovers and the Killer's Cut (play as the killer, on the shared hunt engine `src/engine/hunt.ts`) are built.
- `docs/HORROR-TIER.md`: the planned play-as-the-horror tier in every game (a shared hunt engine: first-tier runs defended by their bots, the player as the horror). Approved; the engine, LATE FEES's Killer's Cut and Elderdark's wood are built, and DEEP CONTRACT's creature is next.
- `docs/kaiju/DESIGN.md`: the fourth game, DOWN THERE (named by the user 2026-10-21; working title FATHOM in code): deep water to kaiju, sharks on the coast down to mechs at the breach.
- `docs/MISSIONS.md`: the approved new missions (security detachment, haulage, salvage, the Keep), the shared held-ground engine, and the build order.
- `docs/OUTBREAK.md`: the second first-tier horror for DEEP CONTRACT (a pathogen turning the workforce against the company), and the rule for which horror a contract gets. Built: `src/mission/outbreak/`, `src/data/outbreak/`, the SICK BAY in `src/ui/sick-bay.ts`.
- `docs/DATA-GAMES.md`: proposal (not built) for games defined in JSON: mechanics as selectable modules, a safe expression language, the screen and theme as data, generated pacing tests.
- `docs/TELEMETRY.md`: anonymous PostHog analytics (published site only, opt-out, events derived from state diffs). Add an event there when a new milestone matters for pacing.

## Non-negotiable requirements

1. **Strict TDD.** Every feature starts as failing tests whose names state the functional goal in plain language. Watch them fail, write the minimum code to pass, refactor while green. Commit at each green. No production code without a test driving it.
2. **Phone and desktop are equally first-class.** The primary real device is an iPhone (Safari). Mobile-first CSS; desktop three-column layout at ≥900px. Tap targets ≥44px, inputs ≥16px font, `100dvh`, safe-area insets, `touch-action: manipulation`, no hover-only affordances, drill uses `pointerdown`.
3. **No backend.** All state lives in the browser (`localStorage`); the build is a static, offline-capable PWA. Moving between devices = export/import save code. The only outbound traffic is optional, fire-and-forget telemetry; the game must never depend on it.
4. **Missions stay self-contained** (for the future Boardroom). Nothing under `src/mission/` may touch the DOM, globals, `Date.now()` or `Math.random()`. Time comes in as `dt`, randomness from the seeded RNG stored in mission state (`m.rng`), and wider-game knowledge only via `MissionContext`.
6. **Horrors are not coupled to scenarios** (user requirement). A horror (`src/mission/organism/`) knows a scenario only through `StorySignals`, the scenario's lexicon (`{placeholders}` in its text) and `HorrorHooks`. A scenario knows the horror only through `horrorProductionMultiplier` and `horrorPressure` (how hard it pushes back on held ground). The one sanctioned exception is a horror's `pairings[scenarioId]` file (e.g. `src/data/organism/nursery.ts`). `tests/mission/kinds.test.ts` enforces this (stub scenario, quiet horror, lexicon coverage).
5. **Horror must not be obvious until ~2 hours of progress.** Act I content is upbeat corporate; Act II tells must each have a mundane explanation. Pacing is enforced by `tests/sim/pacing.test.ts`. If you change economy numbers, run `npm run simulate` and keep those tests green.

## Commands

- `npm test`: vitest (unit, jsdom UI, data invariants, pacing). `npx tsc --noEmit` for types.
- `npm run test:e2e`: Playwright on desktop Chromium plus iPhone 13 emulation (Chromium by default; `E2E_WEBKIT=1` for real WebKit once `sudo npx playwright install-deps webkit` has been run).
- `npm run simulate [overland|extraction|terraform|security|haulage|salvage|all] [outbreak]`: bot playthrough timings per act, for every scenario by default; a second argument runs a different horror.
- `npm run dev -- --host`: test on a phone over the LAN. Debug jumps: `/contract/?debug=act2|act3|act4|terminus|terraform|tf-act2|security|sec-act2|haulage|haul-act2|overland|salvage|sal-act2|outbreak|ob-act2|ob-act3|ob-act4` (`src/core/debug.ts`). Debug jumps only work in dev builds. `?debug=veteran` unlocks every contract and tier and opens the assignment screen (the e2e helper uses it). Dev extras: `&speed=N` (1–100× clock), `&grant=N` (credits), `&flags` (story overlay).
- If the dev server suddenly serves unstyled pages after a CSS edit, its watcher caught the file mid-write: `touch src/styles/*.css`. Prefer the Edit tool over scripts that truncate and rewrite CSS.
- `npm run simulate:late [camp|clinic|insurer|asylum] [drowned|burned|design|patient]`: the same for LATE FEES (a venue, optionally with a crossover killer). `npm run simulate:forest [keep] [hours]` for Elderdark (forest by default). `npm run simulate:board` for the Boardroom, `npm run simulate:clips` for CLIP WORKS. LATE FEES has one dev-only jump, `/late-fees/?debug=member` (every tape and side B stocked), and DOWN THERE one, `/down-there/?debug=veteran` (the Source open). Elderdark debug jumps: `/forest/?debug=keep|keep-deep|veteran` (`src/forest/debug.ts`).
- `npm run build`: typecheck plus static build (all four pages) with service worker. `npm run docs` generates the engine reference into `dist/engine/` (CI runs it after the build). `npm run screenshots` retakes the README screenshots from the dev server. `npm run icons` regenerates PWA icons from sprites.

## Code map and conventions

- `src/mission/`: pure, immutable `(state, …) => state` functions.
  - Core, shared by every contract: `state.ts` (`MissionCore`, discriminated `MissionState`, `composeMission`/`createMission`), crew, the directive engine (goals are named metrics the scenario answers), the story engine, log, lexicon, `kinds.ts` (`ScenarioDef`/`HorrorDef`), `registry.ts`, `tick.ts` (`tickWith` composes scenario → crew → horror → directives → story).
  - Scenarios: `extraction/` (ore, generators, refinery, depth), `terraform/` (reactors, three processing lines, ±10% power allocation, spec match, colonist waves) `security/` (troopers, ammunition fabricators, assault/line split, sentry guns, colony sectors on the shared held-ground engine `src/engine/ground.ts`) `salvage/` (cutters, shoring, the torch dial with hull stress and breaches, a hull governor; derelict compartments on held ground) and `haulage/` (engines, tow cars, the burn dial, fuel at stations, delivery windows, freight strain, an autopilot). Haulage runs two hauls from profiles (`haulage/profiles.ts`): the long haul in space, and `overland`, the short first contract on the road to the space elevator (quiet horror, one ending).
  - Horrors: `organism/` (specimens, containment, infestation) `outbreak/` (Strain KA-11: a workforce SIR model, quarantine, wards, cultures, lockdown; drawn for contracts from six completed by `horrorFor`) `quiet/` (none; proves the decoupling) and `creature/` (driven by the player in the Special Order 0-77 hunt, `src/core/creature.ts`).
  - Typing: scenario code takes `ExtractionMission`/`TerraformMission`, horror code `OrganismMission`; state transitions are generic `<M extends …>(m: M): M`. Tests read fields off a broad `MissionState` with `tests/helpers.ts` (`ext`, `tf`).
- `src/core/`: `GameState = { version, savedAt, profile, mission, boardroom? }`, the store/reducer, offline catch-up (`advance`/`catchUp`, 8h cap), saves (versioned migrations in `save.ts`; **bump `GAME_VERSION` and add a migration for any saved-shape change**), prestige, debug scenarios.
- `src/data/`: content tables only, grouped by axis: `extraction/`, `terraform/`, `organism/` (beats, archive, endings, nursery pairing), plus shared `crew.ts`, `core-story.ts` and `sprites.ts`. Content gets **invariant tests** (unique ids, monotonic costs, every beat reachable, sprite dimensions/palette), not per-item tests.
- `src/ui/`: hand-rolled DOM via `h()`/`setText()` in `dom.ts`; panels are `{ el, render(state) }` registered in `app.ts` with a `visible()` predicate (tabs appear as features unlock) and an optional `attention()` (tab marker). Accessible names and roles are the test hooks (`getByRole`, `aria-label`).
  - Each scenario supplies a `ScenarioUi` (`src/ui/scenarios/`): flow-readout spec, monitor rows, stats, the big action button, systems and upgrades panels, and optional controls (terraform's allocation). The shell mounts only the running scenario's elements into slots.
  - The walkthrough: `src/engine/guide.ts` (pure steps, per-device progress) and `src/engine/ui/guide.ts` (tip and rules page). DEEP CONTRACT's content is in `src/data/guide.ts`. **New scenarios ship with guide steps and a rules page.**
  - `alerts.ts` is the top strip (active directive progress, tired crew); `assignment.ts` is the contract choice (new game, renewal, CFG reassignment).
- The **production flow readout** (`src/ui/flow.ts`) is the game's headline: whichever stage is limiting gets highlighted, and any change in rate gets a call-out. The **operations monitor** (`src/ui/monitor.ts`) shows automation working. Keep new economy features visible there instead of only in panels.
- Sprites are palette-indexed strings (`. a b c d e`) mapped to CSS variables at draw time, so act themes re-tint them. `corruptFrame` glitches them deterministically.
- Story beats: `{ id, act?, when({m, ctx, signals}), entries, effects?, urgent? }`. Entry text may use lexicon `{placeholders}`; horror-specific effects are `{ kind: 'action', action }` (handed to the horror). The engine itself is `src/engine/story.ts`. At most one per tick, spaced by `STORY_MIN_GAP` unless urgent. Repeat-contract beats use the `cycle-` id prefix.
- Match surrounding style: small comments only where intent isn't obvious, short constants at the top of modules, no new dependencies without need.
